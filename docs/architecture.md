# 合同审查 Agent — Codex 实施架构

本方案面向「用户主要依靠 Codex 编码、本人负责业务判断与验收」的开发方式，目标为一周可运行的课程原型。此前文档的双账号、双入口、三栏界面、八类提取、审计标注和演示要求继续纳入。本文收敛技术选择、模块边界和实施顺序。

## 1. 固定技术栈和运行方式

采用一个 Git 仓库，内部按职责划分模块。

| 部分 | 决定 | 对本项目的作用 |
|---|---|---|
| 网页 | React + TypeScript + Vite + 普通 CSS | 组件对应三栏，状态有类型检查，布局可以独立调整 |
| API | Python 3.12 + FastAPI + Pydantic | API 请求、模型返回与结果统一验证 |
| 数据库 | SQLite + SQLAlchemy + Alembic | 保留用户、任务和文件版本，结构变更可迁移 |
| 长任务 | 独立 Python Worker，SQLite jobs 表作为队列 | 页面刷新或 API 重启时仍能继续追踪任务 |
| 文件 | 私有 data/ 目录，由鉴权 API 提供访问 | 原件、报告、编辑稿都有明确归属 |
| 本地聊天 | IndexedDB，按账号/合同/会话标识存储 | 支持浏览器中的历史和草稿 |
| 合同工具 | pypdf、python-docx、rank-bm25 | PDF/Word 解析、结构分块和词法检索 |
| 模型 | TACC 的 Qwen，通过一个 ModelClient 适配 | 以实际课程接口确定请求和排队协议 |
| 邮件 | Microsoft Graph，通过一个 MailClient 适配 | 专用 Outlook 收件、验证码和结果回传 |
| 验证 | pytest + Playwright，合成合同 fixtures | 对账号隔离、证据、重试与实际页面流程做回归 |
| 部署 | 一台 Linux 云服务器，API + Worker，共享持久目录，HTTPS 反向代理 | 与本地保持同一套业务逻辑 |

开发时运行 Vite、API、Worker，Vite 代理 /api。演示/部署时编译前端，由 FastAPI 提供静态资源，API 和 Worker 作为两个服务启动。部署配置在本地流程验收后补齐。依赖初次安装时锁定实际兼容版本。

Codex 编写和验证应用代码。合同运行时由 TACC/Qwen 执行审查。前端展示 Qwen 的审查结果、工具事件、简短行动理由及耗时。

## 3. 三个接口先固定，再做界面与 Agent

**合同 Contract。** 原件上传一次产生 contract_id，包含 owner_id、company_id、file_id、content_hash、parser_version。同一公司只是归档关系，所有合同访问仍然检查 owner_id。同一合同后续问题使用现有 contract_id。

**任务 Job。** 每次提问产生 job_id，包含 contract_id、用户要求、选用的 Skill 快照、规则版本、source、parent_job_id、状态。网页创建和邮件受理均调用同一个 create_job 服务。相同文件的新问题可以产生新任务，重试相同 HTTP 请求用 idempotency_key 去重，邮箱按稳定消息 ID 与附件 ID 去重。

**事件与结果。** 事件包含 job_id、递增序号、阶段、类别、尝试号、时间、说明和工具名。结果保存结构化证据与审计判断，引用指向合同原文。

```json
{
  "category": "automatic_renewal",
  "extraction_status": "verified",
  "evidence": [{"paragraph_id": "P0043", "quote": "Either party may give 60 days' notice."}],
  "facts": {"notice_days": 60, "unit": "calendar_days"},
  "policy_id": "supplier-demo",
  "policy_version": 1,
  "assessment": "pass",
  "explanation": "示例审计清单要求至少提前 30 个自然日，合同为 60 日。"
}
```

上述为合成示例，真实任务中单位及数字都需要证据支持。

Pydantic 是 API 数据结构的定义源，前端类型从 FastAPI OpenAPI 生成。模型返回先通过结构验证，再进入证据验证和业务规则。这样改字段时能同时发现前后端不一致。

## 4. 功能实现顺序与模块边界

### 账户和数据

普通法务可查看自己的合同、问题、事件、模板、风险表和编辑稿。总账户可跨账号查看原件与 Agent 最终风险表及报告。管理员列表返回必要的合同元数据，聊天、过程事件和个人稿维持原权限边界。后端每次文件、事件、报告请求均校验所属关系。

采用邮箱验证码注册、邮箱和密码登录、HttpOnly 会话 Cookie。生产环境启用 HTTPS、安全 Cookie 和写请求的 CSRF 防护。验证码短期有效、一次性消费并限制猜测次数。测试环境可使用显式标识的本地发件箱完成验证，正式部署必须通过真实邮件路径。

浏览器 IndexedDB 保存完整聊天时间线和草稿。服务器保存执行任务所需的问题、状态、事件与产物。每个已完成结果同步到本地缓存，用户点击下载把 DOCX 保存到设备。换设备仍能打开云端合同与任务，历史本地会话只在原浏览器里恢复。账号隔离在同一浏览器内通过命名空间和注销时清空内存完成，服务器权限独立校验。

### 三栏界面

- 顶部放「添加合同」、当前公司、文件名、执行模式和账号菜单。
- 左栏依次列公司、合同、该合同的历史会话，并提供未归类合同入口。
- 中栏包含消息、上传区域、Skill 选择、处理事件与结果卡片。上下文跟随当前合同，追问时传递选中的前序结果 ID。
- 右栏提供「原文 / 风险表 / 编辑报告」标签。PDF 可预览页面，提取文本视图精确高亮引用；DOCX 展示可定位的段落与表格。报告编辑后生成新版本。

### Worker 和 Harness

运行 Harness 是 Python 状态机，维护输入、阶段、上下文、工具观察、验证结果和耗时。每次推进保存事件与阶段输出。Worker 用原子数据库操作领取任务，记录租约和心跳，长模型调用期间也保持心跳。过期租约可重新领取，保存结果时校验领取令牌，阻止过期 Worker 覆盖新结果。SQLite 事务保持短小，模型网络调用在事务外执行。

前端按事件序号轮询，每 1–2 秒获取增量。服务器重启、网页刷新和外部接口失败都能显示任务实际状态。

### 双入口和邮件

网页和邮箱的区别收敛到输入来源、身份识别和交付方式。模型处理阶段接收相同的 JobInput。收件进程负责同步、验证来源、提取附件和提交任务，审查 Worker 负责生成结果，交付进程负责回邮。三者可以由一个 Worker 进程里的独立循环调度，各自持久化进度。

专用 Outlook 通过 Graph 连接，授权流程按个人账号或学校 Microsoft 365 实际条件确定。普通用户邮箱验证与来件身份验证各自记录。可信组织来件自动受理；外部来源无法确认时使用网页发放的提交凭据或由账号持有人确认。一次成功配置后，常规授权来件可自动处理并回传。

保存成品和创建交付记录采用可恢复的一致流程。回邮目标从任务所属账号取值。Graph 接受请求、收件箱实际收到、发送状态不确定分别显示。发送失败可重发已有报告。模型调用和报告生成无需因回邮失败重新执行。

## 5. 有边界的 Agent 决策

```text
确定 Skill 与审查范围
  → 解析合同与稳定段落 ID
  → 按章节/条款/句子层级分块
  → Qwen 分块通读，形成全局导航
  → BM25 + 导航提示定位八类证据
  → Qwen 输出类别事实和原文引用
  → 校验结构、逐字引用与事实依据
  → 必要时扩展相邻段或明确交叉引用，重提取一次
  → 按版本化审计规则判定
  → 保存风险表、回答、报告
  → 网页交付或邮箱回传
```

模型可返回的动作限定为选择允许的审查类别、请求上下文、提出一条澄清问题、返回结果。Harness 验证动作参数后调用对应工具。账号权限、文件访问、收件人、最大重试和预算由程序确定。

第一版语义分块用标题、条款编号、段落和句界，保持语义单元完整。块大小按照已确认的模型上下文预算控制，并给输出预留空间。较长段落拆分时保留原 paragraph_id 和 span 偏移。全局覆盖统计按唯一原文区间计算，重叠区去重。该方法可明确称为「结构感知语义分块」。

第一次审查完成全局导航。追问复用可验证的解析结果和已有导航，缓存键包括合同哈希、解析器、模型、提示词及导航版本。请求新范围时检查已有覆盖，需要时再补充通读。评测分别记录首次处理和复用后的延迟。

自定义 Skill 保存名称、类别、关注字段、审计规则版本和额外关注点。运行时保存不可变快照。自由文本关注点不能覆盖系统权限或执行任意代码。

风险标签使用「符合 / 不符合 / 待核验 / 不适用」。确定性规则处理数值、币种、期限等已校验事实；定性审计要求保留模型说明与人工复核状态。规则必须包含来源、适用合同类型和版本。目前先使用明确标注的示例规则，团队确认真实审计依据后再替换。

## 6. 三种可独立验证的运行配置

| 配置 | 模型、邮箱 | 用途 |
|---|---|---|
| demo | 固定样例响应与本地发件箱，页面显示演示标识 | 随时启动验证账户、上传、进度、导出和界面 |
| test | 可控制的响应、超时、错误 JSON、重复来件等测试替身 | 稳定复现边界情况和失败恢复 |
| live | 真实 TACC、真实 Graph、私有服务器存储 | 最终端到端验收与课程评测 |

三种配置共用业务入口、Agent、权限和报告逻辑，只替换外部适配器。Live 配置缺少必要凭据时清楚报错。演示替身输出不能混入真实模型评测结果。TACC 如使用队列协议，就在 ModelClient 内实现提交/查询/读取结果，而业务层仍使用同一调用接口。

## 7. Codex 的开发里程碑

每个里程碑交付一个可实际操作的增量，并记录验证证据。一天可以完成多个里程碑，顺序由依赖决定。

| 阶段 | Codex 交付 | 用户验收 |
|---|---|---|
| M0 环境和接口探测 | 检查已有代码、锁定环境、启动脚本、最小 schema、TACC 与 Graph 独立连通脚本 | 运行一次本地启动，确认哪些真实连接已经成功 |
| M1 最小完整路径 | 演示账号 → 上传合同 → 持久任务 → 示例提取 → 风险表 → 下载 DOCX | 上传、刷新、打开结果、下载均可操作 |
| M2 真实审查 | 真实 TACC，解析与分块，全局导航，八类检索、校验、重试和 trace | 引用能回到原文，跨段案例显示真实补查 |
| M3 产品工作台 | 三栏、公司归档、账号隔离、同合同追问、Skill 保存、本地聊天、报告编辑 | 账号 A/B 权限与总账户视图通过检查 |
| M4 邮件自动化 | 验证码、Outlook 授权、增量收件、去重、自动回传、失败重发 | 测试邮箱真实发送合同并收到报告 |
| M5 评价和部署 | 三方法对照、回归、云服务器配置、备份说明、1–2 分钟 Demo 与录屏方案 | 独立启动，评测可复现，演示连续成功 |

M0 时就验证外部账号条件，授权等待期间继续 M1。开发时按功能贯穿前端、API、Worker、数据库与产物，以用户操作结果作为完成条件。你主要提供接口权限、样本和业务标准，并体验每个增量。Codex 负责实现、诊断和相关回归。

建议项目只维护三份长期说明：

1. AGENTS.md 记录固定技术栈、权限规则、模式含义和实际启动/验证命令。
2. docs/architecture.md 记录当前方案与接口约定。
3. docs/progress.md 记录已完成和待完成项、外部条件与最近一次验证证据。

这些文件是为本项目选择的协作约定。AGENTS.md 可供 Codex 读取项目指令，其他文档通过任务提示引用。实现时把实际命令补到 README 和 AGENTS.md，避免只留下规划命令。

### 可交给 Codex 的首次实施任务

> 根据 docs/architecture.md 实现合同审查 Web 项目。先检查现有代码和环境，保留可复用实现。按 M0 到 M5 顺序持续推进，每个阶段都从用户实际入口验证。缺少 TACC 或 Graph 凭据时记录具体缺项，完成不依赖它们的 demo 与测试路径。保持三种配置可辨识。优先完成上传、处理、证据查看、导出的完整路径，再扩展账户工作台和邮件。完成后记录启动命令、验证结果、仍未接通的真实服务和下一项工作。

### 后续继续开发任务

> 读取项目约定和 docs/progress.md，先检查记录与实际代码是否一致，继续最早未完成的里程碑。复现当前问题、实现修复，并通过该功能的正常入口验证。更新进度和真实外部接口状态。

## 8. 质量与实验

优先测试会改变交付正确性的边界，包括跨账号读写、引用伪造、合同内指令干扰、重复邮件、Worker 重启、报告版本、错误 JSON、发送超时和本地会话切换。至少用一个浏览器端到端测试覆盖注册/登录、上传、等待、定位证据、下载及追问。

实验保留全文一次调用、BM25 提取、全局通读加 BM25 三个方法。真实比较采用相同模型、解码参数、输出结构与可比合同，统计全部通读、路由、重试成本。CUAD 用于条款提取评价，审计标签另用人工确认的规则样例验证。核心指标为提取命中、误报、证据有效率、总 token、总耗时和失败恢复结果。

演示固定一份短合同和一个跨段续约案例，展现输入、工具动作、证据与风险表，再展示真实收到的结果邮件和总账户原件/成品视图。以彩排时间决定直播或播放录屏。

## 9. 本阶段的交付与依赖

本文件完成了适合 Codex 持续实施的架构设计。原有 Python 草稿仍需验证与集成，完整网站、云部署及真实收发尚未完成验收。

需要提供或确认的外部信息包括课程 TACC 接口样例及权限、专用 Outlook 账号和 OAuth 应用授权、云服务器访问条件、实际审计清单。Codex 可以继续完成本地可运行部分，真实服务的成功以实际调用证据为准。
